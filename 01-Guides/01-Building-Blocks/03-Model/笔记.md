# Model 学习笔记

## 1. 为什么 AgentScope 还需要 Model 抽象

不同供应商的请求字段、流式协议、工具调用格式和 usage 返回值并不完全相同。AgentScope Model 的作用是把这些差异转换为统一接口：输入是 AgentScope `Msg`，输出是 `ChatResponse`。

```python
raw = await model([SystemMsg(...), UserMsg(...)])
```

如果 `stream=False`，`raw` 是一个完整 `ChatResponse`；如果 `stream=True`，`raw` 是异步生成器，需要继续使用 `async for` 消费。

## 2. Credential、Model、Agent 的边界

| 层 | 负责 | 不负责 |
|---|---|---|
| Credential | API Key、base URL 等认证信息 | Prompt、工具执行、会话历史 |
| Model | 单次模型请求、格式转换、重试、流式 chunk | 完整 ReAct 循环和工具真实执行 |
| Agent | 上下文、模型、工具、推理—行动循环 | 供应商底层 HTTP 协议 |

不要把 Credential 当作普通字典打印。Demo 只展示供应商、模型名和 base URL，不输出 Key。

## 3. ChatResponse 与 Agent Event

Model 流产生的是 `ChatResponse` chunk；Agent 流产生的是 `AgentEvent`。

- `ChatResponse` 更接近一次模型 API 的结果；
- `AgentEvent` 覆盖完整 Agent 运行，包括模型、工具、权限和最终回复；
- 流式 Model 中，普通 chunk 是增量，最后一个 `is_last=True` chunk 是聚合结果；
- 因此不能把所有增量和最终聚合文本再次相加，否则会重复。

## 4. 模型参数

常用参数包括：

- `temperature`：控制采样随机程度，但不是“事实正确率”开关；
- `max_tokens`：限制最大输出，不等于上下文窗口；
- `top_p`：另一种采样控制，初学阶段通常不要同时频繁调整；
- `thinking_enable` / `reasoning_effort`：只在对应模型和供应商支持时使用；
- `parallel_tool_calls`：是否允许模型一次生成多个工具调用；
- `context_size`：客户端配置的最大上下文容量。

生产中应为每个具体模型建立经过验证的配置，不要假定同名参数在所有供应商上行为完全一致。

## 5. usage 与成本

最终响应可能包含 `usage`，一般可观察输入 token、输出 token 等指标。它适合用于：

- 请求成本估算；
- 上下文增长告警；
- 不同 Prompt/模型的对比；
- 服务容量规划。

不能假定每个兼容服务都返回完全相同的 usage 字段；代码应允许其为 `None`。

## 6. 工具调用的真实含义

给 Model 传入的是工具 JSON Schema。Model 返回 `ToolCallBlock`，其中包含工具名和参数字符串，但此时：

- 权限尚未必检查；
- Python 工具函数尚未必执行；
- 工具结果尚未回填；
- 模型也尚未基于结果生成最终回答。

这些工作通常由 `Agent + Toolkit` 完成。这也是 `05_model_tool_call.py` 只观察 ToolCallBlock、不真正执行工具的原因。

## 7. 结构化输出

`generate_structured_output()` 可以根据 Pydantic 模型生成字典结果。它比从自然语言中手写正则解析可靠，但仍需要：

- Pydantic 字段和范围校验；
- 枚举和业务规则校验；
- 对缺失字段、供应商不兼容和解析失败进行异常处理；
- 不能因为返回 JSON 就自动信任其中的业务事实。

## 8. 供应商切换

上层代码应该依赖统一的模型构建函数，而不是在 Agent 里散落不同供应商判断。切换时至少验证：

1. 模型是否存在且 Key 有权限；
2. 流式响应格式；
3. 工具调用支持；
4. 结构化输出支持；
5. 上下文窗口与 token 计费；
6. 超时、限流和重试行为。

“兼容 OpenAI API”只说明 HTTP 形状相近，不保证所有能力和参数都完全一致。



AgentScope 的模型层由 API 凭证（Credential）和模型族组成。一个凭证对应一个 API（例如 OpenAI，Gemini，DashScope等），并对应该 API 下的若干模型族（LLM，TTS，Embedding，Realtime）。

Credential 管理“如何访问模型平台”，模型族管理“调用哪一种能力”，具体模型则决定最终使用哪个模型。
