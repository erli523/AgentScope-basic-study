# Tool 学习笔记

## 1. 工具是什么

工具是 Agent 与外部世界交互的能力，例如读取文件、执行命令、查询数据库或调用 HTTP API。模型本身只会生成“我要调用哪个工具、参数是什么”的 `ToolCallBlock`；框架还要完成权限检查、参数解析、真实执行、结果回填和下一轮模型推理。

```text
Model 生成 ToolCallBlock
        ↓
Agent 检查权限
        ↓
Toolkit 查找并调用 ToolBase
        ↓
ToolChunk → ToolResponse
        ↓
工具结果回填 Context
        ↓
Model 再次推理并给出最终回答
```

## 2. ToolBase 的关键字段

| 字段 | 含义 |
|---|---|
| `name` | 暴露给模型的工具名，应稳定、清楚且唯一 |
| `description` | 告诉模型何时使用，不能只写“处理数据”这类模糊描述 |
| `input_schema` | JSON Schema，约束参数名称、类型、必填项和说明 |
| `is_concurrency_safe` | 是否允许多个调用并发执行 |
| `is_read_only` | 工具是否始终无副作用 |
| `is_external_tool` | 是否把执行交给人工或外部系统 |
| `is_state_injected` | 是否需要框架注入 `_agent_state` |

每个子类必须实现 `check_permissions()`。一般工具还要实现 `call()`；外部执行工具设置 `is_external_tool=True` 后，可以不实现真实执行逻辑。

## 3. call 与 __call__

- `call()`：开发者实现业务逻辑；
- `__call__()`：框架入口，负责执行工具中间件并调用 `call()`；
- 不要覆盖 `__call__()`；
- 单元测试可以直接调用工具，但应意识到直接调用可能绕过 Agent 权限流程。

## 4. ToolChunk 与 ToolResponse

工具既可以一次返回一个 `ToolChunk`，也可以流式产生多个 ToolChunk。Toolkit 会把它们合并为最终 `ToolResponse`。

- `ToolChunk.is_last` 表示工具流中的状态；
- `ToolChunk.state` 可以是 running/error 等；
- `ToolResponse.state` 表示最终 success/error/denied/interrupted；
- Agent 会把最终结果转换为 ToolResult 事件和内容块。

## 5. FunctionTool

`FunctionTool` 会从函数名、docstring 和类型注解推导工具 Schema，适合快速包装简单函数。它能把字符串、字典等返回值转换成 ToolChunk。

局限：

- 默认 `is_read_only=False`；
- 默认权限决定为 ASK；
- 复杂权限、动态只读、规则匹配和外部执行更适合直接继承 `ToolBase`；
- 缺少类型注解或 docstring 会让 Schema 和工具描述变差。

当前本机 AgentScope 2.0.3 还有一个兼容性注意点：`FunctionTool` 自动推导包含 `Literal` 等类型的 Schema 时，不要在该 Demo 文件中启用 `from __future__ import annotations`，否则延迟为字符串的类型可能使 Pydantic 动态模型无法完成解析。升级框架后应重新验证此限制是否仍存在。

## 6. 权限与只读性

`is_read_only=True` 适用于永远只读的工具。若只读性取决于参数，应覆盖：

```python
async def check_read_only(self, tool_input: dict) -> bool:
    return tool_input.get("action") == "query"
```

权限决定包括：

| 行为 | 含义 |
|---|---|
| ALLOW | 允许执行 |
| DENY | 拒绝执行 |
| ASK | 请求人工确认 |
| PASSTHROUGH | 交给权限引擎的规则继续判断 |

高风险安全检查可设置 `bypass_immune=True`，避免普通 allow 规则静默放行。权限模式与具体规则会在 Permission System 章节进一步学习。

## 7. 内置工具

常用内置工具包括 Bash、Read、Write、Edit、Glob 和 Grep。Read/Glob/Grep 通常是只读工具；Write/Edit/Bash 可能产生副作用。

文件工具执行“先读后写”：已存在文件必须先通过 Read 写入 `agent.state.tool_context` 缓存，Write/Edit 才能修改。这避免工具基于过期内容盲目覆盖文件。

## 8. 工具中间件

`ToolMiddlewareBase` 只包裹某个工具自身的执行链，适合日志、metrics、参数加工和重试。第一个中间件是最外层：

```text
Logging.before
  Retry.before
    tool.call()
  Retry.after
Logging.after
```

需要访问整个 Agent ReAct、权限事件或模型调用时，应使用 Agent 级 Middleware，而不是工具中间件。

## 9. MCP

Toolkit 可以注册 MCP 客户端并把远端工具转换为 `MCPTool`。工具名采用：

```text
mcp__{server_name}__{tool_name}
```

- Stateful STDIO/HTTP 连接需要显式 `connect()` 和 `close()`；
- Stateless HTTP 每次临时连接；
- MCP `readOnlyHint` 可被 AgentScope 权限系统识别；
- MCP 是外部输入，应限制可启用工具、超时、凭证和返回内容。

## 10. Skill 与工具的区别

Skill 是 Markdown 指令集，不是直接执行能力。Agent 先调用自动注册的 Skill 查看器读取 `SKILL.md`，再根据指令使用已有工具完成工作。

```text
Tool  = 可以调用的动作
Skill = 如何组合动作完成某类任务的说明书
```

## 11. Tool Group

基础工具属于始终激活的 `basic` 组。额外 ToolGroup 默认不暴露，Agent 通过 `reset_tools` 元工具更新激活集合。

这样做的价值：

- 降低工具 Schema 占用的 token；
- 减少模型选错工具；
- 按任务暴露最小能力集合；
- 激活时附带该组专用 instructions。

`reset_tools` 的参数表示最终完整状态，未显式设为 `True` 的非 basic 组会被停用。

## 12. 与校园安防项目的对应关系

在校园安防系统中，可以按 Agent 角色分配不同 Toolkit：

- 发现 Agent：查询设备状态、读取告警；
- 派单 Agent：提交人工确认、创建工单；
- 督办 Agent：查询超时、发送升级通知；
- 复检 Agent：读取复检结果、更新状态。

业务写操作应具备权限、幂等键和审计信息。LangGraph 决定流程到了哪个角色；AgentScope Tool 负责角色可以执行什么真实动作。
