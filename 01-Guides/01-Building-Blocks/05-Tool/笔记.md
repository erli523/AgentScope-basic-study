# 05 Tool — 学习笔记

## 1. 先抓住三个概念

| 概念 | 是什么 |
|------|--------|
| **Tool（ToolBase）** | 单项能力：叫什么、做什么、收什么参数、怎么执行 |
| **Toolkit** | 工具管理器：注册、查找、调用；也管 MCP / Skill |
| **ToolGroup** | 一组工具 / MCP / Skill 的集合，可按场景激活 |

```python
toolkit = Toolkit(
    tools=[x1, x2, x3],
)
```

只传 `tools` 时，它们都进特殊的 **"basic" 组**——该组**始终激活**。  
源码里会自动创建 `basic`，并把构造函数里的 `tools`、`skills_or_loaders`、`mcps` 放进去。

```text
Toolkit
└── basic 组（始终激活）
    ├── Bash
    ├── Read
    ├── Write
    └── Edit
```

再追加 `mcps`、`skills_or_loaders` 或额外 `tool_groups`，就能拓展能力。

## 2. 工具在整条链路里干什么

模型本身只会生成「要调哪个工具、参数是什么」的 `ToolCallBlock`。  
框架还要完成权限检查、参数解析、真实执行、结果回填和下一轮推理：

```text
Model 生成 ToolCallBlock
        ↓
Agent 检查权限
        ↓
Toolkit 查找并调用 ToolBase
        ↓
ToolChunk → ToolResponse
        ↓
工具结果回填 Context
        ↓
Model 再次推理并给出最终回答
```

更细一点（执行前到真正 call）：

```text
模型决定调用工具
        ↓
check_permissions()
        ↓
check_read_only() / match_rule()
        ↓
允许执行
        ↓
__call__()          # 框架入口
        ↓
工具中间件
        ↓
call()              # 业务逻辑
        ↓
返回 ToolChunk
```

## 3. ToolBase：统一接口

`ToolBase` 规定一个工具至少要说明：

| 字段 / 方法 | 含义 |
|-------------|------|
| `name` | 暴露给模型的名字，应稳定、清楚、唯一 |
| `description` | 告诉模型**何时**使用，不能只写「处理数据」 |
| `input_schema` | JSON Schema：参数名、类型、必填、说明 |
| `is_concurrency_safe` | 是否可并发 |
| `is_read_only` | 是否始终无副作用 |
| `is_external_tool` | 是否交给人工 / 外部系统执行 |
| `is_state_injected` | 是否注入 `_agent_state` |
| `check_permissions()` | **必须实现**：执行前权限检查 → `PermissionDecision` |
| `call()` | 一般工具**必须覆盖**：执行逻辑 → `ToolChunk` 或异步生成器 |

外部执行工具设 `is_external_tool=True` 后，可以不实现真实 `call()`。

### 3.1 `call` 与 `__call__`

- `call()`：开发者写业务逻辑  
- `__call__()`：框架入口，跑中间件再调 `call()`  
- **不要覆盖 `__call__()`**  
- 单元测试可直接调工具，但要意识到可能绕过 Agent 权限流程  

### 3.2 ToolChunk 与 ToolResponse

- 可一次返回一个 `ToolChunk`，也可流式多个  
- Toolkit 合并为最终 `ToolResponse`  
- `ToolChunk.is_last` / `state`：流式过程态  
- `ToolResponse.state`：最终 success / error / denied / interrupted  
- Agent 再转成 ToolResult 事件和内容块  

## 4. 自定义工具

一般由四块组成：`name` + `description` → `input_schema` → `check_permissions` → `call`。

```python
class WeatherTool(ToolBase):
    name = "get_weather"
    description = "查询城市天气。"
    input_schema = {
        "type": "object",
        "properties": {
            "query": {"type": "string", "description": "查询词"},
        },
        "required": ["query"],
    }
    is_concurrency_safe = True
    is_read_only = True

    async def check_permissions(
        self,
        tool_input: dict,
        context: PermissionContext,
    ) -> PermissionDecision:
        return PermissionDecision(
            behavior=PermissionBehavior.ALLOW,
            message="Web search is read-only.",
        )

    async def call(self, query: str) -> ToolChunk:
        results = await do_search(query)
        return ToolChunk(content=[TextBlock(text=results)])
```

`ToolBase` = 自定义工具基类；`ToolChunk` = 执行结果的标准格式。

## 5. FunctionTool：把函数快速包成工具

```python
def get_weather(city: str, unit: str = "celsius") -> str:
    """查询天气。"""
    return "..."

toolkit = Toolkit(tools=[FunctionTool(get_weather)])
```

| 参数 | 含义 |
|------|------|
| `func` | 待包装函数 |
| `name` | 覆盖工具名（默认 `func.__name__`） |
| `description` | 覆盖描述（默认 docstring） |
| `is_concurrency_safe` | 默认 True |
| `is_read_only` | 默认 **False** |
| `is_state_injected` | 默认 False |

局限：

- 默认权限常是 ASK  
- 复杂权限 / 动态只读 / 外部执行 → 更适合直接继承 `ToolBase`  
- 缺类型注解或 docstring → Schema 变差  

本机 AgentScope 2.0.3 注意：`FunctionTool` 推导含 `Literal` 等类型的 Schema 时，该 Demo 文件不要写 `from __future__ import annotations`，否则延迟注解可能让动态模型解析失败。升级后再验证。

## 6. 权限与只读性

| 行为 | 含义 |
|------|------|
| ALLOW | 允许执行 |
| DENY | 拒绝执行 |
| ASK | 请求人工确认 |
| PASSTHROUGH | 交给权限引擎规则继续判断 |

`is_read_only=True`：永远只读。若只读性取决于参数，覆盖：

```python
async def check_read_only(self, tool_input: dict) -> bool:
    return tool_input.get("action") == "query"
```

高风险检查可设 `bypass_immune=True`，避免普通 allow 规则静默放行。  
更细的权限模式放到 Permission System 章。

## 7. 内置工具与后端切换

常用：Bash、Read、Write、Edit、Glob、Grep。

- Read / Glob / Grep：通常只读  
- Write / Edit / Bash：可能有副作用  

**先读后写：** 已存在文件须先经 Read 写入 `agent.state.tool_context` 缓存，Write/Edit 才能改，避免基于过期内容覆盖。

**Glob / Grep：**  
- Glob：Unix「全局匹配」文件名模式  
- Grep：底层常用 ripgrep（`rg`），大项目搜索很快  

**后端切换（容易绕）：**  
同一套工具接口不变，但把命令/文件操作交给本机、Docker、E2B 等不同环境。  
通过 `backend` 参数切换；`backend` 实例可从 Workspace 获取，**默认本地**。

## 8. 工具中间件

一开始对「中间件」这个名字不太直观——其实就是包在工具外面的前后处理（不如说「夹在中间的包装」）。

只包裹**某个工具**自己的执行链，适合日志、metrics、参数加工、重试：

```text
中间件 1：前置
  ↓
中间件 2：前置
  ↓
tool.call()
  ↓
中间件 2：后置
  ↓
中间件 1：后置
```

注册顺序决定外层/内层；真正行为还取决于是否调用、调用几次、如何调 `next_handler()`，以及是否改参数/结果/异常。

```python
class LoggingMiddleware(ToolMiddlewareBase):
    async def on_tool_call(
        self,
        tool: ToolBase,
        input_kwargs: dict[str, Any],
        next_handler: Callable[..., AsyncGenerator[ToolChunk, None]],
    ) -> AsyncGenerator[ToolChunk, None]:
        print(f"→ 调用 {tool.name}，参数：{input_kwargs}")
        async for chunk in next_handler(**input_kwargs):
            yield chunk
        print(f"✓ {tool.name} 执行完毕")


bash = Bash(middlewares=[LoggingMiddleware(), RetryMiddleware(max_attempts=3)])
```

要碰整个 Agent ReAct / 权限事件 / 模型调用 → 用 **Agent 级 Middleware**，不是工具中间件。

## 9. MCP

通过 `Toolkit(mcps=[...])` 注册；带状态的客户端须在构造 Toolkit **之前** `connect()`。

```python
client = MCPClient(
    name="filesystem",
    is_stateful=True,
    mcp_config=StdioMCPConfig(
        command="mcp-server-filesystem",
        args=["--root", "/my/project"],
    ),
)
await client.connect()
toolkit = Toolkit(mcps=[client])
```

想表达的是：**MCP 也统一交给 Toolkit 管理。**

工具名形态：

```text
mcp__{server_name}__{tool_name}
```

- Stateful STDIO/HTTP：显式 `connect()` / `close()`  
- Stateless HTTP：每次临时连接  
- `readOnlyHint` 可被权限系统识别  
- MCP 是外部输入，应限制可启用工具、超时、凭证和返回内容  

## 10. Skill 与工具的区别

```text
Tool  = 可以调用的动作
Skill = 如何组合动作完成某类任务的说明书（Markdown）
```

通过 `Toolkit(skills_or_loaders=[...])` 传入（路径字符串 / Skill 对象 / SkillLoader）。  
Agent 先读 `SKILL.md`，再按说明使用已有工具。

## 11. ToolGroup 与 `reset_tools`

`ToolGroup`：带名称和描述的工具 / MCP / Skill 集合，经 `Toolkit(tool_groups=[...])` 设置。  
保留名 `"basic"` 由顶层 `tools` / `mcps` / `skills_or_loaders` 自动构成，始终激活。

额外组默认不暴露；Agent 用元工具 **`reset_tools`** 更新激活集合。

价值：

- 少占 Schema token  
- 少选错工具  
- 按任务暴露最小能力  
- 激活时可附带组专用 instructions  

`reset_tools` 可以理解成：**一个专门用来管理其他工具的工具。**  
其参数表示最终完整状态；未显式设为 `True` 的非 basic 组会被停用。

## 12. 与校园安防项目的对应

可按角色分 Toolkit：

- 发现 Agent：查设备、读告警  
- 派单 Agent：人工确认、创建工单  
- 督办 Agent：查超时、升级通知  
- 复检 Agent：读复检结果、更新状态  

业务写操作应有权限、幂等键和审计。  
**LangGraph** 决定流程到了哪个角色；**AgentScope Tool** 负责角色能执行什么真实动作。
