ToolBase 是所有 Python 工具的基础类，它规定一个工具至少要说明：

工具叫什么：name
工具能做什么：description
接收哪些参数：input_schema
被调用时执行什么逻辑：call()
是否只读、是否支持并发等属性

也就是说，开发者实现工具时，需要遵守这个统一接口。AgentScope 的 ToolBase 正是通过这些字段和 call() 方法定义工具协议。

AgentScope 中的 Bash，Grep，Glob，Read，Write，Edit 工具支持后端切换，即将运行逻辑委派到不同的执行环境中，例如本地文件系统，Docker 容器，E2B 沙箱等。
这句话本身不太好理解 但是他的含义也就是 同一个工具接口不变，但把命令执行和文件操作交给不同的运行环境。
后端切换就是让同一套 Bash、Read、Write 等工具，在不改变 Agent 调用方式的情况下，改为操作本机、Docker 容器或云端沙箱中的文件和命令。

ToolGroup 是带有名称和描述的工具 / MCP / skill 集合，通过 Toolkit(tool_groups=[...]) 接口进行设置。其中保留名 "basic" 由构造函数顶层的 tools、mcps、skills_or_loaders 自动构成，且始终处于激活状态。


ToolGroup 接收与 toolkit 相同的 tools、mcps、skills_or_loaders 参数，再加上一个用于向智能体描述本工具组的 description 字段，以及工具组激活时返回给智能体的可选 instructions 参数。
basic之中的tool始终被激活 使用 ToolGroup 后 可以把工具按业务场景分类：  就可以实现相关的按需激活了
