# 02 Agent — 学习笔记

## 1. Agent 是什么（我怎么理解官网那句话）

官网的说法大致是：

> Agent 是智能体的核心抽象——一个无状态的推理-行动循环引擎，将模型、工具、权限系统、人机交互、上下文管理、中间件、状态管理和事件系统整合到一个统一接口中。

一开始我会把重点落在「**无状态的推理-行动循环引擎**」这几个字上。  
再想想之后，重点更像是：

**以循环作为核心抽象，并统一接入：**

- Message 和 Event
- 工具与权限控制
- 上下文压缩
- 中间件
- 人工确认与中断
- 状态和会话管理

也就是说：AgentScope 的 Agent 是基于 **ReAct（推理—行动）** 往前推的。

它主要负责：

1. 接受消息或事件  
2. 管理上下文（包括上下文压缩、工具结果卸载等）

> 仍有点疑惑：为什么上下文压缩要由 Agent 自身来做？乍一看会觉得有点怪。  
> （对照别的系统：谁判断压缩、谁生成摘要，并不总在同一层——见下表。）

| 场景 | 谁判断是否压缩 | 谁生成压缩内容 |
|------|----------------|----------------|
| Codex Agent 内部 | Codex Agent Loop | 模型或压缩服务 |
| Cursor 原生 Agent | Cursor 平台的 Agent 框架 | 当前使用的模型 |
| 自己开发 AgentScope Agent | 你配置的上下文管理（`context_config` 等） | 你调用的模型 |

## 2. 创建 Agent 时要配什么

常见配置项：

`name`、`system_prompt`、`model`、`toolkit`、`state`、`model_config`、`offloader`、`context_config`、`react_config`

其中：

- **必选：** `name`、`system_prompt`、`model`
- **其他：** 可以先不着急，后面章节再展开

## 3. 三个核心入口

| 方法 | 做什么 |
|------|--------|
| `reply` | 一次性返回最终结果 |
| `reply_stream` | 流式返回事件 |
| `observe` | 只把消息注入上下文，**不**触发 reply / 推理 |

流式分发示例：

```python
async def main():
    msg = UserMsg(name="user", content="总结一下 README 的内容。")
    async for event in agent.reply_stream(msg):
        match event.type:
            case EventType.TEXT_BLOCK_DELTA:
                # 模型返回的流式文本片段
                ...
            case EventType.TOOL_CALL_START:
                # 智能体即将调用工具
                ...
            case _:
                # 思考块、工具结果、回复结束等
                ...

asyncio.run(main())
```

## 4. AgentState：可恢复的状态快照

`AgentState` 是一个 Pydantic 模型，保存恢复智能体所需的全部信息——对话上下文、压缩摘要、权限规则、工具状态和当前 reply 位置等。  
因为是标准 Pydantic 模型，可以序列化成 JSON，存到任意后端。

结构可以简化理解成：

```python
class AgentState(BaseModel):
    session_id: str
    summary: str
    context: list[Msg]

    # 下列字段名以本机 agentscope 版本为准，此处按学习时的理解整理
    reply_id / cur_iter 等运行位置信息
    permission_context: PermissionContext
    tool_context: ToolContext
    tasks_context: TaskContext
    middle_context: dict
```

## 5. 和 Session 存储怎么配合

初始化时可以从存储里拿旧状态，也可以新建：

```python
record = await storage.get_session(user_id, agent_id, session_id)
state = record.state if record else AgentState()
# state 既可以是之前存在 Redis 里的，也可以是新建的 AgentState()

agent = Agent(
    name="my_agent",
    system_prompt="你是一个有帮助的助手。",
    model=DashScopeChatModel(
        credential=DashScopeCredential(api_key="YOUR_API_KEY"),
        model="qwen-max",
    ),
    state=state,
)

result = await agent.reply(UserMsg(name="user", content="..."))

await storage.update_session_state(
    user_id=USER_ID,
    agent_id=AGENT_ID,
    session_id=SESSION_ID,
    state=agent.state,
)
```

注意：

- 若 session 尚不存在，`update_session_state` 会抛出 `KeyError`
- 首次创建请用 `upsert_session` 建立记录，后续轮次再切到 `update_session_state`
