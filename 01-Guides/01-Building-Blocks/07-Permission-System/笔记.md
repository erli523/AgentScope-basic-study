# 07 Permission System — 学习笔记

## 1. 权限系统在干什么

概念上可以想成：Agent **每一次工具调用**都会被查询 / 拦截，最后给出三种动作之一：

| 结果 | 含义 |
|------|------|
| **ALLOW** | 允许执行 |
| **DENY** | 拒绝执行 |
| **ASK** | 先问用户，再决定 |

决策通常来自三块：**Rules（规则）**、**Mode（模式）**、**Built-in Checks（内置运行时检查）**。

## 2. 三个来源分别是什么

### 2.1 Rules（规则）

针对**具体工具 + 调用模式**的明确规定：这类命令该 ALLOW / DENY / ASK。

```python
permission_context = PermissionContext(
    mode=PermissionMode.DEFAULT,
    deny_rules={
        "Bash": [
            PermissionRule(
                tool_name="Bash",
                rule_content="rm -rf:*",
                behavior=PermissionBehavior.DENY,
            ),
        ],
    },
)
```

规则一般会写死在配置里；也可以在运行时动态写入——例如先 ASK，用户选了 ALLOW 后，把建议规则写进 `PermissionContext`。

一条规则至少要说清：

| 字段 | 作用 |
|------|------|
| `tool_name` | 哪个工具（`Bash` / `Read` / `Write` / 自定义名…） |
| `rule_content` | 匹配哪一类参数调用（前缀通配、glob、或对序列化参数精确匹配等） |
| `behavior` | ALLOW / DENY / ASK |
| `source` | 来源标记（`userSettings` / `projectSettings` / `session`…） |

`tool_name` 只定「哪个工具」；`rule_content` 再定「这个工具的哪一类调用」。

示例：对 Bash，凡命中 `npm run …` 都 ALLOW，规则来自项目配置：

```python
PermissionRule(
    tool_name="Bash",
    rule_content="npm run:*",
    behavior=PermissionBehavior.ALLOW,
    source="projectSettings",
)
```

### 2.2 Mode（模式）

**没有明确规则命中时**的全局默认策略——更像「默认站哪边」。

| Mode | 自己的理解 | 典型场景 |
|------|------------|----------|
| `DEFAULT` | 最稳妥的默认：未明确允许就倾向询问 | 日常默认 |
| `EXPLORE` | 偏严格的只读 | 读代码、分析、规划 |
| `ACCEPT_EDITS` | 面向开发：工作目录内编辑更容易放行，其它高风险仍收紧 | 人在场的改代码 |
| `DONT_ASK` | 无人值守：不问人，ASK 往往变 DENY | CI / 定时任务 |
| `BYPASS` | 全信任感更强：大量检查被跳过 | 沙箱或完全可信环境 |

实际项目里未必五种都用；很多时候更关心「要不要人确认」和「只读还是可写」。

### 2.3 Built-in Checks（内置检查）

不是事先写死的那张规则表，而是工具在**运行时看真实参数**，判断这次调用是不是只读、是否危险等（例如 Bash 识别 `ls` / `git status`，或发现危险路径 / 注入风险）。

## 3. 决策顺序怎么理解

一开始会以为「每次调用一定 Mode → Rules → Built-in 全走一遍」。更准确是：

```text
Mode
  ↓
决定采用哪一套检查流程
  ↓
按该流程检查 Rules、只读性质、Built-in Checks …
  ↓
得到 ALLOW / DENY / ASK
```

所以**不一定**每次都同一套路径，要看当前 Mode 怎么设计。  
也就能理解文档为什么会紧接着给「各 Mode 下的权限设计」。

### 各 Mode 一览（精简）

| Mode | 核心行为 |
|------|----------|
| `DEFAULT` | 未明确允许时多要确认；Bash 识别只读命令可自动 ALLOW；Read/Glob/Grep 常 PASSTHROUGH，没命中 allow 仍可能 ASK |
| `ACCEPT_EDITS` | 工作目录内文件操作更易放行；Bash 文件类命令仅当目标都在工作目录内才易自动放行 |
| `EXPLORE` | 只读放行，修改拒绝；用户配置的 DENY/ASK 仍优先于只读自动放行 |
| `BYPASS` | 跳过大量检查（含不少 safety ASK）；**仍尊重**显式 deny/ask 与工具自身 DENY——危险路径要用 deny 护住 |
| `DONT_ASK` | 把各类 ASK 转为 DENY，非交互下更安全 |

## 4. 配置挂在 AgentState 上

权限相关状态放在 `agent.state.permission_context`：

```python
agent = Agent(
    name="my_agent",
    system_prompt="...",
    model=model,
    state=AgentState(
        permission_context=PermissionContext(
            mode=PermissionMode.DEFAULT,
        ),
    ),
)

# 运行中也可改 mode
agent.state.permission_context.mode = PermissionMode.EXPLORE
```

带工作目录（给 `ACCEPT_EDITS` 等用）：

```python
state = AgentState(
    permission_context=PermissionContext(
        mode=PermissionMode.ACCEPT_EDITS,
        working_directories={
            "/my/project": AdditionalWorkingDirectory(
                path="/my/project",
                source="userSettings",
            ),
        },
    ),
)
```

规则示例（allow + deny 一起配）：

```python
PermissionContext(
    mode=PermissionMode.DEFAULT,
    allow_rules={
        "Bash": [
            PermissionRule(
                tool_name="Bash",
                rule_content="npm run:*",
                behavior=PermissionBehavior.ALLOW,
                source="userSettings",
            ),
        ],
        "Write": [
            PermissionRule(
                tool_name="Write",
                rule_content="src/**",
                behavior=PermissionBehavior.ALLOW,
                source="userSettings",
            ),
        ],
    },
    deny_rules={
        "Bash": [
            PermissionRule(
                tool_name="Bash",
                rule_content="rm:*",
                behavior=PermissionBehavior.DENY,
                source="userSettings",
            ),
        ],
    },
)
```

只读探索 Agent 的最小写法：

```python
Agent(
    name="explorer",
    system_prompt="...",
    model=model,
    state=AgentState(
        permission_context=PermissionContext(mode=PermissionMode.EXPLORE),
    ),
)
```

## 5. 自己留的注意点

- 权限必须由**代码**执行，不能只写在 system prompt 里指望模型自觉。  
- 直接 `tool.call()` 可能绕过权限系统；正式执行应走 Agent 流程。  
- `BYPASS` 不等于「deny 也没用」——显式 deny/ask 仍要配。  
- `DONT_ASK` 适合无人值守：**不问人，但默认偏拒绝**，再靠精确 allow 放行。
